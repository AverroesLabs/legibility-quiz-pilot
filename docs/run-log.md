For about 9 minutes both processes made the same calls, appended to the same `calls.jsonl` files and could overwrite each other's `versions/{rem,imp}.md`, `gap-meta.json` and `takes-gap.jsonl`. Account usage rose from $437.06 to $477.51 in that time; part of it is duplicate spend (my rough estimate: under $20).
- **Fix:** both processes killed at 05:39 UTC (corrected from "about 05:57" after the watchdog flagged it; time from the log files' timestamps), one process relaunched at 05:39:56 (`logs/gap.log`; the mixed log of the two is kept as `logs/gap-duplicate-run.log`). The relaunch replays the last logged response for every call key, so each paper's versions, meta, takes and ratings are rebuilt from one consistent set of calls. Nothing from the duplicate period is used without being regenerated by the single run.
- **Lesson:** after a background launch, check `ps` for the process before relaunching, rather than trusting the failure of the commands that followed it.
